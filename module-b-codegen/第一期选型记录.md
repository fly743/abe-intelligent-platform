# B 模块 CP-ABE 选型与验证记录

## 当前决定

采用 [junwei-wang/cpabe](https://github.com/junwei-wang/cpabe) 的 BSW 实现。固定提交通过本地工件准备脚本接入 B 模块构建；当前已有内存密码适配，完整生成和受限执行流程尚未实现。详细比较见 [密码实现对比](../docs/B模块密码实现对比.md)。

曾验证 Predenc 2.0.0 在 Java 17 上具备基本加解密能力，但该实现拒绝重复属性策略，不符合项目要求。根据决定，已移除其正式依赖、策略转换和验证代码；此处只保留结论供追溯。

## BSW 已执行验证

- 下载上游 master 源码 ZIP，其 SHA-256 为 `0EDD9DF1AA74686D6E73C287FB4965F67375339107AF7E0E76AF2E791228782E`。使用附带 jPBC 1.2.1 JAR，将上游源码按 Java 8 目标编译后在 OpenJDK 17.0.18 上运行。该散列记录本次文件，master 地址本身并非固定版本。
- `BswIntegrationCheck.java` 使用本项目解析器及属性编码，检查两个含重复属性的策略各 8 种属性组合，以及包含 `of` 的属性策略的 4 种组合，实际解封装与逻辑预期一致。
- `BswCandidateCheck.java` 在独立进程写入和恢复公开参数、主密钥及密文，对授权和拒绝属性验证中文文本；AES-GCM 密文被修改后拒绝解密。临时密钥文件已清理。该试验对群元素字节使用 SHA-256 派生 AES 密钥，仅为功能验证，不证明整体安全性。
- 清理其他候选后，B 模块 Java 17 离线编译及上述两项 BSW 核查再次通过。离线 `clean compile` 首次因缓存缺少 clean 插件未运行，随后使用 `compile` 成功重新编译；Maven 输出环境提示 `Access is denied`，最终退出码为 0。

## 已知问题及后续工作

- 上游仓库标注 GPL-2.0；其 jPBC JAR 的原始发行许可、固定获取来源和项目分发义务尚需核查。上游构建依赖项目内 JAR 和 system scope，不能直接当作可靠的正式依赖。
- 上游反序列化截断输入时抛出数组越界异常；公开参数序列化遗漏 `f`，本次密钥生成与解密路径可运行，但依赖该字段的委托功能尚不可用。
- 上游解密会修改密文策略树状态；不能假定共享密文对象并发安全。源码使用固定旧配对参数，不能凭功能通过推断安全等级。
- 下一步固定源码及依赖，引入隔离的密码适配层，明确密钥保存、输入边界和并发策略；正式接入完成前不能声称重复属性已在系统端到端流程中支持。

## 固定依赖与内存适配（2026-11-14）

- 固定上游提交 `0e71de17ed64729f2de811503a7958673691e77a`，源码 ZIP SHA-256 为 `E0298FF2F23073AC141E333C01C3063E9544ABAB66E921425647FFD7FE47978B`。准备脚本验证后编译 BSW 及准备随源码提供的 jPBC JAR，生成项目 `.bsw-local` 下的本地 Maven 工件；构建成功。jPBC 发行许可仍需核查。
- `BswCryptoService` 实现内存 setup、属性密钥生成、策略加密和解密；属性经同一编码转换，群元素密钥材料经 HKDF-SHA256 派生 AES-256-GCM 密钥，序列化的策略密文作为 GCM 关联数据。明文上限 1 MiB；当前没有可持久化的密钥/密文格式或对外接口。
- 实际核查重复属性策略的两条授权路径、未授权拒绝、含 `of` 属性、空明文、不同系统实例隔离及数据密文修改拒绝，均符合预期。解密前创建独立策略树且服务方法同步；尚未进行压力验证或安全审计。上游不满足策略时会写标准错误输出。

## 推送前补充核查（2026-11-14）

- 修复原本地工件位于 `target`、被 `mvn clean` 删除的问题；现在使用 `.bsw-local` 并通过 `.gitignore` 排除。使用隔离 Maven 缓存、删除其中已有 BSW 工件后，准备脚本与 `mvn clean compile` 成功；重复属性及跨进程 PoC 再次通过。
- 上游 BSW 仓库的 COPYING 为 GPL 第 2 版；本项目根目录尚无已跟踪的许可证。随源码附带的 jPBC 1.2.1 JAR 内未找到许可证文件，试图获取 [jPBC 1.2.1 原始发行包](https://sourceforge.net/projects/jpbc/files/jpbc_1_2_1/) 时未获得可解析的压缩包，具体许可和 JAR 与原始发行包一致性尚未确认。`.bsw-local` 不纳入 Git，准备脚本在本机获取上游源码与 JAR；是否公开分发以及相应许可义务仍需根据最终分发方式确认。
- 上游源码硬编码 Type A 配对参数（约 512 位基域、160 位子群）并以 SHA-1 处理属性。作为历史参考，[RFC 5091 第 9 节](https://www.rfc-editor.org/rfc/rfc5091.html#section-9)将类似 512/160 Type-1 参数列在 80 位等级，而不是 128 位；该 RFC 针对 IBE，不能直接作为此 BSW 实现的精确安全评估。也不能从 AES-256 推断整体达到 256 位安全强度。
- 结论：可作为毕设的功能原型继续开发；尚不能称为生产安全方案。决定公开分发前应解决许可核查，论文和文档应写明旧参数、依赖和验证范围。
