# 团队本机部署：知识检索

每位成员在自己的电脑上运行 Qdrant，并用项目里的语料生成本机向量数据。以下步骤适用于 Windows PowerShell；首次导入和之后的检索会调用百炼 Embedding，可能产生费用。

## 首次部署

**准备：**拉取包含正式语料的项目代码；安装 Java 17、Maven 和 Docker Desktop 并启动 Docker；确认已配置百炼 Embedding API Key 环境变量 `ABE_RAG_EMBEDDING_API_KEY`。不要把 Key 提交到 Git。

### 1. 启动数据库并构建项目

在项目根目录打开 PowerShell，依次执行：

```powershell
$repo = (Get-Location).Path
docker compose -f deploy/docker-compose.yml up -d
if ($LASTEXITCODE -ne 0) { throw 'Qdrant 启动失败，请检查 Docker Desktop' }
mvn -pl module-d-integration -am install -DskipTests
if ($LASTEXITCODE -ne 0) { throw '构建失败，请检查 Maven 输出' }
```

### 2. 启动服务

继续在同一个窗口执行：

```powershell
$env:QDRANT_COLLECTION = 'abe_knowledge'
$env:ABE_CORPUS_DIR = Join-Path $repo 'module-a-rag\docs'
$env:ABE_RAG_INCLUDE_QA = 'false'
$env:ABE_RAG_INGEST_ENABLED = 'true'
$env:ABE_RAG_ALLOW_RECREATE = 'false'
# 若尚未配置到系统环境变量，在启动窗口显式设置；两个 key 都必需
# $env:ABE_RAG_EMBEDDING_API_KEY = 'sk-...'
# $env:ABE_RAG_CHAT_API_KEY = 'sk-...'
mvn -pl module-d-integration spring-boot:run
```

服务启动后保持该窗口运行。首次启动时若 Qdrant 尚未就绪，请稍等再重试。

### 3. 导入一次知识笔记

**另开一个 PowerShell 窗口**，检查本机集合：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8080/internal/rag/health'
```

确认 `status` 为 `UP`、`collection` 为 `abe_knowledge` 且 `points` 为 0，再执行一次：

```powershell
$result = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/internal/rag/ingest'
$result
$result.failures
```

`failures` 应为空。当前版本可参考 7 个 Markdown 文件、106 个片段（含 `notes/abe-engineering.md`），语料或切分规则变化后数量可能不同。如果已有数据或出现失败，先检查原因，不要反复导入或重建集合。

### 4. 关闭入库开关并验证检索

回到运行服务的窗口，按 `Ctrl+C` 停止服务，然后执行：

```powershell
$env:ABE_RAG_INGEST_ENABLED = 'false'
mvn -pl module-d-integration spring-boot:run
```

在另一个窗口测试：

```powershell
$q = [uri]::EscapeDataString('什么是 KP-ABE？')
Invoke-RestMethod "http://127.0.0.1:8080/internal/rag/search?q=$q&topK=3"
```

返回相关片段即表示检索链路可用。问答闭环用同一份检索结果加 DeepSeek 生成：

```powershell
$q = [uri]::EscapeDataString('CP-ABE 的密文由哪些部分组成')
$r = Invoke-RestMethod -Method Post "http://127.0.0.1:8080/internal/rag/ask?q=$q&topK=5"
$r.answer
$r.citations
```

`refused=true` 表示证据不足或检索为空，`citations` 是答案实际引用到的片段。`ABE_RAG_CHAT_API_KEY` 必须在**启动服务的同一个窗口**里设置；缺失时 `/ask` 返回 401，而 `/health` 仍然显示 `UP`——health 不校验 key。

## 以后怎么启动

无需再次导入。启动 Docker Desktop，在项目根目录运行 `docker compose -f deploy/docker-compose.yml up -d`。然后执行 `mvn -pl module-d-integration spring-boot:run`。如果沿用首次导入的同一窗口，确认 `ABE_RAG_INGEST_ENABLED` 已设为 `false`。

如服务提示缺少 Key，请确认启动服务的 PowerShell 进程能读取已配置的 `ABE_RAG_EMBEDDING_API_KEY`；如果只在其他临时窗口设置过，需要在当前窗口配置，或使用已设置该变量的环境。知识库数据保存在各自电脑的 Docker 卷里，不随 Git 同步。不要运行 `docker compose down -v`，该命令会删除数据卷。

## 在 Harness 里启用问答插件

Java 服务跑起来后，在 Harness 侧安装 `harness-plugin/abe-qa`（包名 `harness-plugin-abe-qa`，当前 0.1.2）。安装源就是仓库里的这个目录，不需要 npm 包或单独仓库。

```powershell
# 1) 启动 Harness（首次会创建 ~/.dsh/profiles/web）
cd D:\projects\deepseek-harness
pnpm dsh web

# 2) UI：设置 -> 插件 -> 添加插件 -> 填 D:/ABE-Program/harness-plugin/abe-qa
#    显示“已关闭”属正常，不要手动开

# 3) 写用户 patch 层（第三方 bundle 不在合成器白名单，必须这步）
D:\ABE-Program\scripts\setup.ps1

# 4) 干净重启，然后在新 token 页面里调 abe_rag_health
Get-Process node -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 2
Test-NetConnection 127.0.0.1 -Port 3080 -InformationLevel Quiet   # 必须 False
cd D:\projects\deepseek-harness; pnpm dsh web
```

Java 服务不在默认地址时，在启动 Harness 的窗口设置 `$env:ABE_RAG_BASE_URL = 'http://127.0.0.1:8080'`。安装、契约与排错详见 `harness-plugin/abe-qa/README.md`。

## 启动 B 代码生成服务

`abe_codegen_verify` 依赖 8081 上的独立服务。首次运行先准备 BSW 工件并编译：

```powershell
$env:JAVA_HOME = 'C:\Users\Jary\.jdks\ms-17.0.18'
powershell -ExecutionPolicy Bypass -File .\module-b-codegen\scripts\prepare-bsw.ps1
$MVN = "C:\Users\Jary\.m2\wrapper\dists\apache-maven-3.9.14-bin\1cb7fhup6b5n3bed6kckbrnspv\apache-maven-3.9.14\bin\mvn.cmd"
& $MVN -pl module-b-codegen compile
```

然后用 `scripts\start-codegen.ps1` 启动，**不要**直接跑 `mvn -pl module-b-codegen spring-boot:run`：

```powershell
.\scripts\start-codegen.ps1
```

原因：`spring-boot:run` 的工作目录是 `module-b-codegen`，而 `abe.codegen.module-directory` 的默认值是相对路径 `module-b-codegen`，两者拼接会变成 `module-b-codegen\module-b-codegen\target\classes`。服务能正常启动，但每次 verify 都返回：

```text
outcome=ENVIRONMENT_UNAVAILABLE
message=模块或本地依赖未编译准备
```

脚本用绝对路径覆盖该配置。执行阶段还需要 Docker Linux 引擎和固定 JDK 镜像：

```powershell
docker pull eclipse-temurin@sha256:5465815640e10433422217335e15a523a3e57021a1f2ae0fc3849380d237979f
```

镜像未准备时 verify 仍返回 HTTP 200 且 `generated.status=SUCCESS`（源码生成成功），只是 `execution.outcome=ENVIRONMENT_UNAVAILABLE`，这是设计好的降级行为。

另外，Maven 若配置了 `<mirrorOf>*</mirrorOf>`，会把 pom 里 `file:///.../.bsw-local/repository` 的自定义仓库一并镜像掉，导致 `com.abe.vendor:bsw-core` 解析失败。处理方式是把 `.bsw-local/repository/com` 复制进 `~/.m2/repository/com` 并删除 `*.lastUpdated` 失败标记，不需要改全局 settings。

## QA 语料

默认导入和检索的是知识笔记，`.qa.md` 不会自动入库；QA 文件已随代码提供，需要时可单独导入 `abe_knowledge_qa`。两个集合不会自动混合检索。开关变量名是 `ABE_RAG_INCLUDE_QA`（对应 yml 的 `abe.rag.ingest.include-qa`），不要写成 `ABE_RAG_INGEST_INCLUDE_QA`。

如需初始化 QA 集合，在首次部署窗口停止服务后执行以下命令。目录必须不存在，避免混入旧文件：

```powershell
$qaRoot = Join-Path $repo 'module-a-rag\target\team-qa-import'
$qaFolder = Join-Path $qaRoot 'faq'
if (Test-Path -LiteralPath $qaRoot) { throw '临时目录已存在，请先检查内容' }
New-Item -ItemType Directory -Force -Path $qaFolder | Out-Null
Get-ChildItem -LiteralPath (Join-Path $repo 'module-a-rag\docs\faq') -Filter '*.qa.md' -File | Copy-Item -Destination $qaFolder
$env:QDRANT_COLLECTION = 'abe_knowledge_qa'
$env:ABE_CORPUS_DIR = $qaRoot
$env:ABE_RAG_INCLUDE_QA = 'true'
$env:ABE_RAG_INGEST_ENABLED = 'true'
$env:ABE_RAG_ALLOW_RECREATE = 'false'
mvn -pl module-d-integration spring-boot:run
```

在另一个窗口检查 `/internal/rag/health`，确认集合为 `abe_knowledge_qa`、状态为 `UP`、点数为 0，再按第 3 步导入并检查 `failures`。当前版本可参考 5 个 QA 文件、135 个片段。完成后停止服务，恢复笔记检索并关闭入库：

```powershell
$env:QDRANT_COLLECTION = 'abe_knowledge'
$env:ABE_CORPUS_DIR = Join-Path $repo 'module-a-rag\docs'
$env:ABE_RAG_INCLUDE_QA = 'false'
$env:ABE_RAG_INGEST_ENABLED = 'false'
mvn -pl module-d-integration spring-boot:run
```

遇到问题时：`/ingest` 返回 403，检查启动服务的窗口是否已开启入库并重启；健康状态为 `DOWN`，检查 Docker 和 Qdrant；导入失败，检查 Key、网络和返回的 `failures`。本机开发开关不是用户认证，未来共享或对外部署需要另行配置安全保护。

## 自检脚本

服务启动后，在项目根目录：

```powershell
.\scripts\rag-smoke.ps1        # 13 条问答冒烟；模型侧偶有波动，建议连跑两次
.\scripts\eval-recall.ps1      # Recall@5，报告写到 module-a-rag/evaluation/reports/
.\scripts\probe-scores.ps1     # 阈值扫描：正样本 vs 不可回答问题
```

依赖关系：`rag-smoke.ps1` 读 `scripts/rag-cases.json`，`eval-recall.ps1` 读 `module-a-rag/evaluation/qrels.json`，`probe-scores.ps1` 读 `evaluation/qrels.json` 与 `evaluation/negative-cases.json`。三个脚本都需要 Java 服务在运行。

## 语料更新流程

改了 `module-a-rag\docs` 下的笔记后，按这个顺序走，避免“改了但检索没变”：

1. **改语料**：只动 `papers\` 和 `notes\`；`.qa.md` 默认不入库，不作为检索语料。
2. **清洗标题页码**：从 PDF 复制的内容常带 `[BSW 2007, PDF 第2页]`。先 dry-run 看预览，再决定是否覆盖：

   ```powershell
   .\scripts\clean-corpus-headings.ps1          # 预览写到 docs\.cleaned-preview
   .\scripts\clean-corpus-headings.ps1 -Apply   # 确认后覆盖
   ```

   覆盖完必须删掉 `.cleaned-preview`：它在 `docs\` 下，会被入库扫描到，导致点数翻倍。
3. **重建集合**：门控变量需为 true 且服务已重启：

   ```powershell
   curl.exe -sS -X POST "http://localhost:8080/internal/rag/ingest?recreate=true"
   curl.exe -sS "http://localhost:8080/internal/rag/health"
   ```

   `points` 应等于切分后的片段数（当前参考 106）；比预期翻倍时先检查预览目录。
4. **跑评测**：`.\scripts\eval-recall.ps1`，把 `Recall@5` 与 `evaluation\reports\` 里上一次报告对比。
5. **同步标注**：若改了章节标题文字，`evaluation\qrels.json` 里的 `section` 子串要一起改，否则会出现假 miss。
6. **提交**：语料、qrels/脚本与文档一起提交，并在记录里写清本次点数与 Recall 变化。
