# 团队本机部署：知识检索

每位成员在自己的电脑上运行 Qdrant，并用项目里的语料生成本机向量数据。以下步骤适用于 Windows PowerShell；首次导入和之后的检索会调用百炼 Embedding，可能产生费用。

## 首次部署

**准备：**拉取包含正式语料的项目代码；安装 Java 17、Maven 和 Docker Desktop 并启动 Docker；确认已配置百炼 Embedding API Key 环境变量 `ABE_RAG_EMBEDDING_API_KEY`。不要把 Key 提交到 Git。

### 1. 启动数据库并构建项目

在项目根目录打开 PowerShell，依次执行：

```powershell
$repo = (Get-Location).Path
docker compose -f deploy/docker-compose.yml up -d
if ($LASTEXITCODE -ne 0) { throw 'Qdrant 启动失败，请检查 Docker Desktop' }
mvn -pl module-d-integration -am install -DskipTests
if ($LASTEXITCODE -ne 0) { throw '构建失败，请检查 Maven 输出' }
```

### 2. 启动服务

继续在同一个窗口执行：

```powershell
$env:QDRANT_COLLECTION = 'abe_knowledge'
$env:ABE_CORPUS_DIR = Join-Path $repo 'module-a-rag\docs'
$env:ABE_RAG_INCLUDE_QA = 'false'
$env:ABE_RAG_INGEST_ENABLED = 'true'
$env:ABE_RAG_ALLOW_RECREATE = 'false'
mvn -pl module-d-integration spring-boot:run
```

服务启动后保持该窗口运行。首次启动时若 Qdrant 尚未就绪，请稍等再重试。

### 3. 导入一次知识笔记

**另开一个 PowerShell 窗口**，检查本机集合：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8080/internal/rag/health'
```

确认 `status` 为 `UP`、`collection` 为 `abe_knowledge` 且 `points` 为 0，再执行一次：

```powershell
$result = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/internal/rag/ingest'
$result
$result.failures
```

`failures` 应为空。当前版本可参考 6 个 Markdown 文件、92 个片段，语料或切分规则变化后数量可能不同。如果已有数据或出现失败，先检查原因，不要反复导入或重建集合。

### 4. 关闭入库开关并验证检索

回到运行服务的窗口，按 `Ctrl+C` 停止服务，然后执行：

```powershell
$env:ABE_RAG_INGEST_ENABLED = 'false'
mvn -pl module-d-integration spring-boot:run
```

在另一个窗口测试：

```powershell
$q = [uri]::EscapeDataString('什么是 KP-ABE？')
Invoke-RestMethod "http://127.0.0.1:8080/internal/rag/search?q=$q&topK=3"
```

返回相关片段即表示检索链路可用；目前尚未接入 DeepSeek，返回的不是最终问答。

## 以后怎么启动

无需再次导入。启动 Docker Desktop，在项目根目录运行 `docker compose -f deploy/docker-compose.yml up -d`。然后执行 `mvn -pl module-d-integration spring-boot:run`。如果沿用首次导入的同一窗口，确认 `ABE_RAG_INGEST_ENABLED` 已设为 `false`。

如服务提示缺少 Key，请确认启动服务的 PowerShell 进程能读取已配置的 `ABE_RAG_EMBEDDING_API_KEY`；如果只在其他临时窗口设置过，需要在当前窗口配置，或使用已设置该变量的环境。知识库数据保存在各自电脑的 Docker 卷里，不随 Git 同步。不要运行 `docker compose down -v`，该命令会删除数据卷。

## QA 语料

默认导入和检索的是知识笔记，`.qa.md` 不会自动入库；QA 文件已随代码提供，需要时可单独导入 `abe_knowledge_qa`。两个集合不会自动混合检索。

如需初始化 QA 集合，在首次部署窗口停止服务后执行以下命令。目录必须不存在，避免混入旧文件：

```powershell
$qaRoot = Join-Path $repo 'module-a-rag\target\team-qa-import'
$qaFolder = Join-Path $qaRoot 'faq'
if (Test-Path -LiteralPath $qaRoot) { throw '临时目录已存在，请先检查内容' }
New-Item -ItemType Directory -Force -Path $qaFolder | Out-Null
Get-ChildItem -LiteralPath (Join-Path $repo 'module-a-rag\docs\faq') -Filter '*.qa.md' -File | Copy-Item -Destination $qaFolder
$env:QDRANT_COLLECTION = 'abe_knowledge_qa'
$env:ABE_CORPUS_DIR = $qaRoot
$env:ABE_RAG_INCLUDE_QA = 'true'
$env:ABE_RAG_INGEST_ENABLED = 'true'
$env:ABE_RAG_ALLOW_RECREATE = 'false'
mvn -pl module-d-integration spring-boot:run
```

在另一个窗口检查 `/internal/rag/health`，确认集合为 `abe_knowledge_qa`、状态为 `UP`、点数为 0，再按第 3 步导入并检查 `failures`。当前版本可参考 5 个 QA 文件、135 个片段。完成后停止服务，恢复笔记检索并关闭入库：

```powershell
$env:QDRANT_COLLECTION = 'abe_knowledge'
$env:ABE_CORPUS_DIR = Join-Path $repo 'module-a-rag\docs'
$env:ABE_RAG_INCLUDE_QA = 'false'
$env:ABE_RAG_INGEST_ENABLED = 'false'
mvn -pl module-d-integration spring-boot:run
```

遇到问题时：`/ingest` 返回 403，检查启动服务的窗口是否已开启入库并重启；健康状态为 `DOWN`，检查 Docker 和 Qdrant；导入失败，检查 Key、网络和返回的 `failures`。本机开发开关不是用户认证，未来共享或对外部署需要另行配置安全保护。
