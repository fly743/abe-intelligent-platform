# B 模块密钥与密文持久化设计

## 目标与边界

使不同进程能够恢复系统参数、用户密钥及密文，验证满足策略时解密成功、属性不足时拒绝，并对损坏文件提供明确错误。当前 `BswCryptoService` 的对象仅绑定同一内存实例，不能跨进程使用；本文描述待实现方案。

## 数据类型

- 系统参数：格式版本、算法标识、系统标识和 BSW 公开参数。
- 主密钥：格式版本、系统标识和 BSW 主密钥，仅供授权方管理，不应写入日志或代码仓库。
- 用户密钥：格式版本、系统标识和 BSW 用户密钥，属性编码须与策略转换一致。
- 密文：格式版本、系统标识、BSW 策略密文、HKDF salt、AES-GCM nonce 和密文及认证标签。

系统标识应由规范化的公开参数计算，用于发现不同系统的数据误配；标识本身不是完整性或真实性证明。禁止直接将未校验的外部字节交给上游反序列化器。

## 实施顺序

1. 核对上游二进制格式、长度字段及嵌套结构，明确可接受的总长度、元素大小、属性数和树深度；设计版本化封装并在调用上游前逐项校验。
2. 分离系统初始化、用户密钥生成及公开参数加密等职责；恢复时验证系统标识，明确公开参数序列化遗漏 `f` 对现有功能的影响，暂不提供依赖该字段的委托功能。
3. 定义密钥保存与保护方式，密文与密钥分别处理；避免将临时明文密钥提交到仓库或输出到日志。
4. 在独立进程完成生成、保存、恢复和解密验证，覆盖重复属性、拒绝访问、截断或超长数据、系统误配及密文篡改；清理验证产生的密钥文件。
5. 更新模块说明，记录格式版本、限制、实际结果和未覆盖的安全问题。

## 现有风险

上游反序列化对损坏输入可能抛出数组越界，部分长度字段可导致过量内存分配；仅限制文件总大小不足以证明内部长度安全。上游公开参数恢复遗漏 `f`，且密码参数和 jPBC 许可已有待核查事项。持久化实现须避免把这些问题伪装成已解决。

## 当前进展（2026-11-15）

已对照上游源码梳理主密钥、用户密钥及密文结构，实现 `BswBinaryValidator` 的长度、数量、策略树及尾随数据预检；内存加解密流程已在反序列化策略密文前调用该检查。Java 17 编译通过，重复属性的正常解密和伪造负长度拒绝已作一次实际验证。

该检查只验证结构边界，不验证群元素的密码学有效性；公开参数的安全解析、版本化格式、密钥保护和跨进程恢复仍未实现。主密钥和用户密钥预检目前尚无正式导入调用方。

## 上游格式核对（实现前）

固定提交的 `SerializeUtils` 使用大端四字节长度或计数。公开参数依次为配对参数字符串、`g`、`h`、`gp`、`g_hat_alpha`；主密钥依次为 `beta`、`g_alpha`；用户密钥为 `d`、组件数及每个组件的属性字符串、`d`、`dp`；策略密文为 `cs`、`c` 和递归策略树。策略树节点保存门限和子节点数，叶子再保存属性及两个群元素。字符串和群元素均以四字节长度开头。

公开参数恢复直接使用输入中的配对描述创建配对对象，因此仅校验描述长度不够；实现时应在调用上游前将其与受支持的固定描述逐字节比较，并检查其余字段和尾随数据。上游序列化未保存 `f`，恢复后的公开参数不支持依赖 `f` 的委托操作。上述核对不构成群元素有效性验证或安全审计。

## 持久化接口（2026-11-15）

`BswCryptoService` 支持导出公开参数、主密钥、用户密钥和密文的字节数组，并通过 `restore`、`importUserKey`、`importCiphertext` 恢复。`restore` 可不传主密钥，此时不能生成用户密钥。格式以 `ABEB` 魔数、1 字节版本（1）、1 字节类型（1 公开参数、2 主密钥、3 用户密钥、4 密文）、32 字节系统标识、4 字节大端载荷长度和载荷组成。密文载荷依次为四个带 4 字节长度的字段：BSW 密文、32 字节 salt、12 字节 nonce、AES-GCM 密文和标签。系统标识是上游公开参数字节的 SHA-256，用于误配检测，不提供真实性或防篡改保证。

密钥导出结果是**明文敏感数据**，本模块不实现密钥文件存储或保护；调用方应使用受访问控制的密钥管理系统，并在持久化及传输时提供认证加密。不要写入日志、仓库或普通临时目录；调用方还应尽量缩短字节数组的生命周期。密文由 AES-GCM 验证，BSW 策略密文为关联数据；系统标识和密钥封装本身不带认证。恶意修改密钥或公开参数不一定能被检测。

导入时限制封装大小、长度及类型；公开参数限定为固定配对描述，BSW 用户密钥和策略树检查数量、长度、深度和尾随数据。这些只是结构边界检查，不验证群元素的密码学有效性，也不保证上游对所有恶意群元素字节安全。公开参数恢复仍缺少 `f`，不提供委托；固定旧配对参数及 jPBC 许可问题仍未解决，不应将该原型视为生产安全方案。

已在两个独立 Java 进程中保存和恢复四类数据，验证重复属性策略的一条授权路径、属性不足拒绝、系统误配、截断用户密钥、错误长度、损坏公开参数和 AES-GCM 密文篡改拒绝；验证文件已清理。这些检查不构成安全审计，未覆盖所有畸形群元素及并发场景。

## 输入边界加固与补充验证（2026-11-15）

实际运行固定参数的 jPBC 1.2.1 `Field.getLengthInBytes()`，得到 G1、G2、GT 均为 128 字节，Zr 为 20 字节。预检现按上游各字段对应的类型精确限制这些长度；这依赖当前固定参数和依赖版本，升级时须重新核对。长度正确仍不意味着元素有效，也不能排除恶意元素触发上游异常。

已使用 `crypto-poc/BswPersistenceCheck.java` 在独立进程间通过管道交换验证数据，无明文密钥文件。检查重复属性策略的两条授权路径、拒绝、恢复主密钥后生成用户密钥、公开参数单独恢复、不同系统数据误配、四种数据的截断、版本和类型错误、超长或尾随数据、元素长度与数量异常、配对描述篡改及 AES-GCM 密文篡改。可先编译模块，再运行 `./module-b-codegen/scripts/check-persistence.ps1`。上游属性不满足时会向标准错误输出提示。

验证仍未穷举畸形群元素、策略树深度及所有损坏组合；密钥和公开参数的真实性保护及正式密钥存储仍需实现。旧配对参数和 jPBC 许可限制不变。

## 团队演示用口令保护（2026-11-15）

已选择方案 A：团队成员作为共同维护演示系统的可信管理员，可以通过受控渠道共享演示用主密钥文件与保护口令；按角色生成不同属性的用户密钥用于展示授权和拒绝。持有主密钥的成员可以签发任意属性密钥，因此该演示不把团队管理员视为相互隔离的对手。不要将口令或密钥提交到 Git，`.gitignore` 不是访问控制。

`BswCryptoService.exportProtectedMasterKey`、`exportProtectedUserKey` 返回口令保护后的字节；`restoreProtected`、`importProtectedUserKey` 恢复。`BswProtectedKeyFiles.saveNew(path, bytes)` 只新建文件，不覆盖；`read(path)` 有文件长度上限。调用方负责创建仓库外或受保护的目录、设置访问权限和备份，写入失败可能留下不完整文件。文件辅助类只检查封装标记和长度，实际认证发生在恢复时。原有明文导出接口仍存在，不能用它作为正式文件存储接口。

保护格式 `ABKP` v1：大端魔数 4 字节、版本 1 字节、类型 1 字节（2 主密钥、3 用户密钥）、PBKDF2 迭代次数 4 字节、16 字节随机 salt、12 字节随机 nonce、4 字节密文长度、AES-GCM 密文及 16 字节标签。v1 固定 PBKDF2-HMAC-SHA256 600000 次，派生 256 位 AES 密钥；格式头完整作为 GCM 关联数据，内部加密载荷为现有带系统标识的 `ABEB` 密钥封装。固定迭代次数避免不可信文件任意控制 KDF 资源开销；以后变更参数须定义兼容的版本并评估实际性能。

口令使用 `char[]` 传入，不由模块保存或清除调用者的数组；调用方应在结束时清除，避免通过命令行参数、日志或仓库传递。选择足够强且唯一的口令，受保护文件仍可被离线猜测口令；遗失口令无法恢复。模块尽力清理临时密钥字节，但 Java 和上游对象不保证内存中所有副本均被擦除。相同口令保护多个文件时每个文件使用随机 salt 和 nonce。认证加密不能阻止删除、回滚旧文件，也不能保证公开参数来源可信；应通过独立可信渠道核对公开参数摘要或另行建立签名信任。该保护层不改变固定旧配对参数及上游限制，尚未经过安全审计。

实际验证：独立进程写入和读取受保护文件，恢复主密钥和用户密钥并完成授权解密；验证拒绝用户、错误口令、文件截断、数据和头部修改、密钥类型误用、系统误配、禁止覆盖、拒绝原始明文封装以及重复保护的随机性。验证结束清理临时文件。可运行 `./module-b-codegen/scripts/check-persistence.ps1` 复现。

## 公开参数指纹与接入说明（2026-11-15）

新增 `publicKeyFingerprint` 和 `verifyPublicKeyFingerprint`，使调用方能够在恢复前将公开参数与独立取得的可信指纹比较；它们不会自动建立信任或强制所有恢复路径执行核对。主密钥和用户密钥的序列化及恢复过程对可控的临时字节副本尽力清零，JVM 和上游对象仍可能保留副本。团队的签发、分发、恢复和演示流程见 [团队演示接入说明](B模块团队演示接入说明.md)。
