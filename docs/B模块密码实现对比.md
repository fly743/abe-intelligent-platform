# B 模块 CP-ABE 候选实现对比

核查日期：2026-11-14。目标是在 Java 17 项目中支持 AND、OR、括号和重复属性策略，生成 Java 示例并验证加密解密。功能实测不等同于独立密码安全审计。

| 对比项 | Cryptimeleon Predenc 2.0.0 | junwei-wang/cpabe（BSW 候选） |
| --- | --- | --- |
| 重复属性 | 当前 Waters 实现拒绝重复 MSP 叶子，不能满足完整策略要求 | 访问树允许重复叶子；已对两个重复策略的全部属性子集进行实际封装和解封装比对 |
| Java 17 | 发布版本实际编译和运行通过 | 仓库源码用 `javac --release 8` 编译后在 Java 17 运行通过；原构建脚本配置 Java 6，不能直接以 Java 17 原样编译 |
| 普通文本 | 已验证 KEM、库内派生函数和 AES-GCM 跨进程恢复 | 已验证群元素经 SHA-256 派生密钥配合 AES-GCM 的固定场景；该实验不证明派生方案的整体安全性 |

| 稳定性 | 作者声明实验性；Maven 进程曾报告线程清理警告 | 固定旧配对参数；反序列化输入边界不足；解密会修改密文策略状态，不能假设共享对象并发安全 |

## 当前选择

对于项目必须支持的重复属性策略，已决定选择 BSW。固定提交已通过准备脚本接入模块构建，内存适配已验证；完整系统尚未打通，仍需核查依赖许可和参数，并设计跨进程密钥存储及安全反序列化。Predenc 的旧验证代码及正式依赖已清理，保留本表作为选型记录；依靠简单代数改写无法保证支持所有一般的重复属性表达式。

## 适配验证与可修补问题

新增 `BswPolicyConverter` 将策略树转为 BSW 后缀表达式。上游实现把包含 `of` 的任意名称误当成门限运算符，因此转换器将属性编码为 `a` 加 ASCII 字节的十六进制；密钥生成必须采用相同的 `encodeAttribute` 映射。编码区分大小写、无歧义，避免用户原始属性碰撞运算符。

Java 17 下实际调用 BSW：对 `(A AND B) OR (A AND C)`、`(A OR B) AND (A OR C)` 的 8 个属性子集，以及 `professor AND 2of2` 的 4 个属性子集，分别比较策略布尔结果和真实解封装结果，全部一致；满足时恢复的群元素一致。此结果覆盖所测案例，不代表所有策略均已穷尽验证。

可在外围适配中处理的内容包括：按相同规则编码属性；对输入长度和格式做限制；每次恢复独立密文对象以避免共享可变状态；统一异常和返回值。公开参数缺失 `f` 可以通过版本化序列化修补，或在首版不提供密钥委托并明确限制；不能将这两个选择混为已经验证的修复。配对参数和密码学安全性不是一般格式错误，未经核查不应自行修改并宣称安全。
